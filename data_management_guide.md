# OSCAR Data Management and Administration Guide

This guide provides administrators with detailed information on how to manage the OSCAR database, what the different pieces of information represent, and how to access data both inside and outside the database.

## 1. Database Administration

The OSCAR platform uses a PostgreSQL (with PostGIS) database to store configuration, system states, and observation data.

### Accessing the Database Configuration
1. In the OSCAR Admin UI, navigate to the **Databases** tab on the left-hand accordion.
2. Select **PostGIS Database** to view or modify the connection settings.
3. *Note on Tuning:* For larger sites (more than 10 lanes or many cameras), you may need to increase the memory, cache, and connection pool buffers. The PG Data directory (created the first time the database runs) contains the `postgresql.conf` file where you can apply performance-tuning parameters.

### Data Purging and Retention
OSCAR includes an automated `DatabasePurger` that runs in the background to manage database size:
- **Non-Occupancy Data:** Hourly, the purger automatically deletes high-volume telemetry (Gamma counts, Neutron counts, speed, etc.) that occurs *outside* of an active occupancy window, leaving a small buffer around the event to ensure no important data is lost.
- **Connection Status:** Routine connection status logs are purged hourly based on retention settings.
- **Daily File Exports:** At midnight (UTC), the system exports the day's lane data to a CSV "Daily File" and then purges the raw daily file records from the database to save space.

## 2. Understanding Database Information

The database is heavily structured around the OpenSensorHub (OSH) standard. Key concepts include:

*   **Lanes and Nodes:** A "Node" represents the server instance. A "Lane" represents an operational sensing unit (e.g., an entrance gate) that aggregates one or more Radiation Portal Monitors (RPMs) and cameras.
*   **Events & Occupancies:**
    *   An **Occupancy** is a specific time-bounded window representing a vehicle or person passing through the lane.
    *   An **Event** is often alarm-oriented (e.g., a Gamma or Neutron spike) associated with that occupancy. The database stores the timestamp, sensor telemetry, and spectral data (if applicable) linked to these events.
*   **Adjudications:** When an operator reviews an alarm in the OSCAR Viewer, their response is recorded as an adjudication. This includes the reviewer's ID, the outcome, assigned codes, notes, and any follow-up actions. Adjudication records are tied directly to the specific Lane and Event.
*   **Client / Site Info:** Stores the bounding box coordinates of the site and paths to site diagrams.

## 3. Information Available Outside the Database (File System)

Not all data is kept in the relational database. Large binary files, reports, and exported archives are stored in the OSCAR File Repository (a file system area managed by the application).

### Accessing Files
Files can be accessed programmatically via the API at `/sensorhub/buckets` or physically retrieved from the node's application directory (under the `Files` folder). Role-based access control determines which users can retrieve specific file categories.

### Key File Types

#### A. Daily Files
*   **What they are:** Machine-generated CSV outputs representing a summary of the day's events for each lane.
*   **When they are created:** Automatically generated at midnight (UTC) by the Database Purger.
*   **Where to find them:** Stored in the `Daily Files` subfolder within the file repository. These files are functionally similar to Rapiscan's native daily file formats.

#### B. Video Files
*   **What they are:** Video clips captured by the lane cameras during an occupancy.
*   **Retention Policy:** Video storage can grow massive. The **OSCAR Service Module** configuration dictates the video retention policy.
    *   Administrators can set a *Time to Retention (days)* limit.
    *   Rather than deleting the entire video to save space, OSCAR can perform **Frame Retention** (e.g., keeping only 3 to 5 keyframes of the event) and deleting the rest of the heavy video file.

#### C. Spreadsheet Imports (CSV)
*   **What they are:** The `config.csv` files used to bulk-import or backup Lane configurations.
*   **Where to find them:** Stored in the `spreadsheets` bucket.

#### D. Reports and Adjudication Evidence
*   **Reports:** PDF or CSV reports generated by users via the OSCAR Viewer (e.g., site-wide statistics, per-lane reports).
*   **Adjudication Evidence / N42 Files:** Spectral data files (N42 format) used by the Web ID API for isotope analysis. Because these contain sensitive radiological profiles, access to adjudication evidence files can be strictly restricted based on user roles in the Admin UI's **Security** tab.
*   **Site Diagrams:** Image files (PNG/JPG) uploaded to represent the physical layout of the nodes and lanes on the Viewer map.
